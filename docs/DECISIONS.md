# DECISIONS

Things examined, found correct or deliberate, and **not to be re-raised**. If a
future session rediscovers one of these as a "bug", the answer is here.

*Last updated: 2026-08-25*

| # | finding | verdict | reasoning |
|---|---|---|---|
| 1 | `latest/` and `stable/` duplicate every file in `image-files/` | by design | They are build outputs of `update.sh`, committed so the Docker build context is self-contained and a tag is reproducible. Edit `image-files/` only. |
| 2 | `IBC_VERSION` may differ between `Dockerfile.template` and the channel Dockerfiles | by design | `detect-ibc-release.yml` bumps the templates only and deliberately skips `update.sh`; the next IB Gateway release propagates it. Comment is in the workflow. The gap seen on 2026-08-25 (templates `3.24.1`, `latest/` `3.24.0`, `stable/` `3.23.0`) was closed the same day by regenerating both channels on request; it will reopen at the next IBC bump, which is normal. |
| 3 | `README.md` duplicates `template_README.md` | by design | `README.md` is generated by `envsubst` in `detect-releases.yml`. Edit the template. |
| 4 | Published host ports map to 4003/4004, not the documented API ports 4001/4002 | correct | `set_ports()` binds the API to container loopback and socat forwards it. Documented in `CLAUDE.md` and `docs/RUNBOOK.md`. |
| 5 | `dotenv-linter:latest` reports ~29 `UnorderedKey` findings on `.env-dist` | not a defect | The pinned pre-commit hook is `0.5.0`; the Docker image is 3.x and stricter. `.env-dist` is kept aligned with upstream; reordering it is churn. |
| 6 | `stop_ibc()` in `run.sh` uses broad `pkill` patterns | correct in context | It runs **inside** the container, where those patterns match only its own children. The rule against broad `pkill` applies to the host. |
| 7 | `MD013` (line length) is disabled in `.markdownlint.yaml` | deliberate | `README.md` is generated from `template_README.md`, and most long lines are option tables whose width their content sets. Any manual reflow is undone at the next release. Decided 2026-08-25. |
| 8 | `bastion/Dockerfile` carries `# hadolint ignore=DL3025` | deliberate | The healthcheck uses bash `/dev/tcp` redirection, which JSON exec form cannot express. Rewriting it would change behaviour to satisfy a style rule. Decided 2026-08-25. |
| 9 | `MD036` (emphasis-as-heading) is disabled in `.markdownlint.yaml` | deliberate | `CLAUDE.md` prescribes a `*Last updated: YYYY-MM-DD*` vintage line under headings throughout `docs/`. That is metadata, not a heading, and the rule cannot tell them apart. Decided 2026-08-25. |
| 10 | A change to `image-files/` was propagated by copying into `latest/`/`stable/` instead of running `update.sh` | deliberate | `update.sh` also regenerates the channel Dockerfiles, which would have pulled `IBC_VERSION` 3.24.1 into both channels - bumping `stable` from 3.23.0 ahead of its release cycle. Copying the changed scripts keeps the `image-files == latest == stable` invariant for scripts while leaving the version drift in #2 intact. Decided 2026-08-25. |
| 11 | The `tests/container` suite is not run in CI | deliberate | It needs a built gateway image, and `build.yml` uses `push: false` / `load: false`, so no image reaches the runner. Loading one would roughly double the build job for a property the unit suite already pins at the script level. Run it locally after touching `run.sh`, `common.sh` or `run_socat.sh`. Decided 2026-08-25. |
| 12 | `stable` ships IBC `3.24.1`, the same as `latest`, rather than an older IBC | deliberate, 2026-08-25 | Regenerating both channels was requested so the new `IBC_SHA256`/`ZULU_SHA256` verification would reach the published images now rather than at the next release. It moved `stable` from IBC `3.23.0`. Both channels were then built locally and both checksum steps reported `OK`. |
